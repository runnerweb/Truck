# 용차 매칭 시스템

## 파일 구성
| 파일 | 역할 |
|---|---|
| `Code.gs` | 구글 Apps Script 백엔드 (모든 데이터는 구글시트에 저장) |
| `common.js` | 공통 스크립트 — **여기에 API_URL 한 곳만 입력** |
| `style.css` | 공통 디자인 |
| `login.html` / `register.html` | 로그인 / 회원가입 |
| `home.html` | 로그인 후 '용차일 보기' · '용차일 등록하기' 버튼 |
| `post.html` | 용차일 등록 |
| `browse.html` | 용차일 보기 (카드 → 달력 → 날짜 상세 → 용차 의뢰하기) |
| `notifications.html` | 알림 (수락하기 / 거절하기 / 매칭 완료) |
| `schedule.html` | 내 스케줄 (매칭 완료된 일정, 상대 기사/요청자 정보) |
| `index.html` | 기본 주소 접속 시 로그인 페이지로 이동 |

## 설치 순서

### 1) 구글시트 + Apps Script
1. 새 구글시트를 만든다 (예: `용차매칭_DB`). **탭은 직접 만들 필요 없음.**
   - ⚠️ 이전 버전에서 만든 `계정` 탭이 있다면 **삭제하거나 새 시트를 사용**하세요. (컬럼 구성이 바뀌었습니다)
2. 확장 프로그램 → Apps Script → `Code.gs` 내용을 통째로 붙여넣기
3. 상단 함수 선택에서 **`setup`** 을 골라 ▶ 실행 → 권한 승인
   - `계정 / 로그인기록 / 세션 / 용차일 / 의뢰 / 알림` 탭이 헤더와 함께 자동 생성됩니다.
4. 배포 → 새 배포 → 유형 **웹 앱** → 실행 계정 **나**, 액세스 **모든 사용자** → 배포
5. 나온 **웹 앱 URL** 복사

### 2) 프론트엔드
1. `common.js` 맨 위의 `API_URL` 값을 위 URL로 교체 (이 한 곳만 수정)
2. GitHub 새 저장소에 **모든 html / css / js 파일**(`Code.gs`, `README.md` 제외 가능)을 드래그 앤 드롭으로 업로드 → Settings → Pages 활성화
3. `https://아이디.github.io/저장소/login.html` 로 접속

### 3) 코드를 고쳤을 때
Apps Script는 수정 후 **배포 관리 → 새 버전**으로 다시 배포해야 반영됩니다. (URL은 그대로)

## 동작 방식 요약
- **로그인 데이터 자동 기록**: 로그인할 때마다 `로그인기록` 탭에 일시/아이디/결과가 쌓이고 `계정`의 최근로그인이 갱신됩니다.
- **비밀번호**: 평문 저장 없이 salt + SHA-256 해시로만 저장. 5회 연속 실패 시 10분간 잠금.
- **단가**: 기본 1,100원 / 지번 +200원(=1,300원) / 직접 설정(1~100,000원). 최종 금액은 서버에서 다시 계산합니다.
- **매칭 흐름**: 용차일 등록(A) → 용차일 보기에서 날짜 선택 후 '용차 의뢰하기'(B) → A에게 알림 → A가 수락/거절 → B에게 결과 알림(수락 시 '매칭 완료' 화면 + 상대 연락처 공개).
  같은 날짜에 의뢰가 여러 건이면, 한 명을 수락하는 순간 나머지는 자동 마감됩니다.
- **알림**: 앱을 열어둔 동안 30초마다 확인해 팝업으로 띄웁니다. (앱을 닫았을 때의 푸시 알림은 스토어용 앱으로 만들 때 추가)

## 설정값 (`Code.gs` 맨 위 `CONFIG`)
- `REQUIRE_APPROVAL` : `true` 로 바꾸면 가입 후 `계정` 탭의 상태를 관리자가 `승인`으로 바꿔야 로그인됩니다. (기본 `false`)
- `BASE_PRICE`, `JIBUN_EXTRA`, `MAX_PRICE` : 단가 기준값
